║  0.  HOW TO USE THIS FILE                                                     ║
╚══════════════════════════════════════════════════════════════════════════════╝

  There are three layers. Two are built once. One runs per client.

    LAYER 1 — THE LIBRARY (this file). A curated menu of vetted directions,
              one set per vertical. Built once. This is it.

    LAYER 2 — THE GUARDRAILS (Section 1). Rules the shared components and the
              QA gate must enforce so no build can ship the AI tells.
              Wired into the template once.

    LAYER 3 — THE SELECTION (Section 2). ~10 minutes of judgment per client:
              pick the preset, confirm/nudge, choose ONE signature, load real
              content, run the critique gate. This is the part that cannot be
              automated. It is small. It is also the whole game.

  Core truth this file exists to enforce:

    Combinatorics produces PERMUTATIONS of one base. Permutations of a generic
    base are still generic. VARIETY IS NOT DISTINCTIVENESS. The tell was never
    the colour — it is every section sharing the same bones. Presets give each
    vertical DIFFERENT BONES; the guardrails stop any build from collapsing
    back to the template default.

  When making improvements: cite the preset and the guardrail by name. Never
  say "make it look better" — say "apply LANDSCAPING preset, enforce


╔══════════════════════════════════════════════════════════════════════════════╗
║  1.  THE GUARDRAILS  —  the quality floor (enforced every build)             ║
╚══════════════════════════════════════════════════════════════════════════════╝

  ── BANNED BY DEFAULT (a build with any of these must be fixed or justified in
     a _comment before it ships) ─────────────────────────────────────────────

    B1  The uniform section header. Every section using centered eyebrow ->
        serif H2 -> muted one-line subtitle. This is the #1 AI tell.

    B2  Card-everything. All content sections as identical white rounded cards
        on a tint. Uniform radius + shadow + padding reads as machine-made.


    B4  CLUSTER #1 — the single most common AI-design fingerprint. WIDENED in
        v3.16 from a palette rule to a COMBINATION rule, and it is now
        typeface-agnostic:
            pale-warm background (~#F4F1EA)
          + centred heading block (eyebrow -> heading -> subtitle, all centred)
          + warm-earth accent (~#C67B5C / #B5651D)
        Any two of those three, plus centred, is already suspect. All three is
        BANNED regardless of what typeface sits on top. (Note: the
        ui-ux-pro-max pack's "Nature Distilled" style IS this combination — do
        not use it. It is the trap, not the answer.)

    B5  DELETED in v3.16 — "serif display as a default" was banned here, and it
        measured the wrong thing.
        Take the offending pattern and swap the serif for a grotesque: the tell
        survives, because it was never the typeface. Keep the serif and change
        the background, the alignment and the accent: the tell is gone.
        The variables are alignment, background temperature and accent hue —
        which is what the widened B4 now measures. The `press` kit (Fraunces)
        stays, and a serif H1 is a judgement call about the client, not a rule.

    B6  Decorative filler with no job: floating monogram circles, emoji as
        section icons (leaf / calendar / tick), ornamental glyphs.

    B7  Placeholder rendering live: TODO strings, lorem, "REQUIRED", empty
        image boxes. A placeholder on a live page is a critical defect.

    B8  Dead vertical space: no empty band taller than ~160px, especially

    B9  Template hero: "big number + small label + gradient accent" unless the
        data genuinely IS the story.

    B10 The badge card (added v3.28). An icon in a circle or tile, stacked
        over a bold title and one grey sentence, inside a bordered rounded
        box, repeated in a grid. It is the most recognisable generated
        pattern there is. A checklist is set as a checklist: hanging tick,
        text on one edge, a rule between entries.

    B11 The repeated action (added v3.28). The same phone number or the same
        button more than once in one screen. Measured on a pipeline demo:
        the number four times above the fold. Repetition reads as a
        generator filling slots, not as urgency. One primary action per
        screen; the header, hero and services row each say it once.

    B12 Equal-weight photo grids (added v3.28). Six photos in six equal
        frames is a thumbnail index: nothing leads, so the eye has nowhere
        to start. One photo leads and the rest support it, chosen by ORDER
        in the intake.
        NOT reviews. Reviews are deliberately set as a row of equal review
        cards in the platforms' own form (initial, name, Google / Facebook
        mark, stars when stated), because that is the form people already
        read as real. Jordan's call, Oct 2026: an editorial pull-quote
        layout was tried and rejected for exactly that reason.

    B13 The box as the default container (added v3.28). Border + radius +
        padding around a form, a fact, a list. A box is for a thing you
        click, a surface that must separate from its ground, or an idiom
        the reader already knows as a card (a review). Everything else is
        grouped by a rule, an edge or space.

    B14 Default-stack type (added v3.28). Inter, Space Grotesk, Poppins,
        Open Sans, Roboto, Montserrat, Outfit, Plus Jakarta Sans as a
        site's display or body face. They are what a generator reaches
        for first, so they are what a reader has seen on every generated
        page. No kit loads Inter or Space Grotesk any more. Type comes
        from the kit table (KIT_FONT_FACES) or the Style Picker; the
        TYPE lines in the section 3 presets below are superseded where
        they name one of these.

    B15 The pill as the default label (added v3.28). Suburbs, badges and
        tags each in an outlined pill is a tag cloud. A list of place
        names is set as a line of names. Pills stay available per client
        (usage.areaStyle), they are just not the default.

  ── ENFORCED FLOOR (true of every build, no exceptions) ─────────────────────

    G1  ALIGNMENT VARIATION. At most half the sections centered. At least two
        sections lead left-aligned or content-first. Section.astro must NOT
        default every section to center.

    G2  CONTAINER VARIATION. Max 2 card-grid sections per page. Others use
        editorial blocks, text lists, or full-bleed treatments.
        (v3.28: a pipeline demo was measured at FIVE boxed sections of nine:
        services, why us, reviews, about, contact. Reviews keep their cards
        on purpose (B12); the other four no longer draw boxes, so the limit
        holds by construction on the default variants instead of by
        remembering to check.)

        ENCODE THE SUBJECT (roofline, horizon contour, rule-line) — never
        generic decoration.

    G4  ONE SIGNATURE. Exactly one memorable element per site, taken from the
        preset. Everything else stays quiet. (Chanel rule: before it ships,
        remove one accessory.)

    G5  REAL CONTENT ONLY. Real copy, real photos, or an honest photo-free
        layout. hasPhotos is an explicit boolean; it flips true only when
        files physically exist in public/images/.

    G6  TYPE SCALE. One display face, one body face. Scale defined for
        display / h2 / body / caption and used consistently.

    G7  QUALITY BASELINE. Responsive to 360px. Visible keyboard focus.
        prefers-reduced-motion respected. Contrast per the checked palettes.

  ── QA GATE (impeccable + this checklist; failing = do not ship) ────────────

        [ ] Are >50% of sections centered?            -> fail (G1)
        [ ] More than 2 card-grid sections?           -> fail (G2)
        [ ] Pale-warm bg + centred head + earth accent? -> fail (B4)
        [ ] Any emoji/monogram/placeholder visible?   -> fail (B6/B7)
        [ ] More than one signature element?          -> fail (G4)
        [ ] Any dead band >160px?                     -> fail (B8)
        [ ] Icon-badge cards in a grid?               -> fail (B10)
        [ ] Same number/button twice in one screen?   -> fail (B11)
        [ ] Homepage photos all at one size?          -> fail (B12)

║  2.  THE SELECTION PROCESS  —  ~10 min of judgment per client                ║
╚══════════════════════════════════════════════════════════════════════════════╝

    STEP 1  Pick the vertical preset (Section 3).
    STEP 2  Confirm/nudge the palette. Swap the ACCENT if the client's own
            brand demands it; keep the BASE — the base carries the identity.
    STEP 3  Confirm/nudge the type. Keep unless there is a real reason.
    STEP 4  Choose the ONE signature element for THIS business (from the
            preset's options, or a client-specific one you can justify).
    STEP 5  Load real content + photos. No lorem, no placeholders.
    STEP 6  CRITIQUE GATE. Ask out loud: "Would I produce this exact page for
            any other client in this vertical?" If yes -> change one axis
            (palette shade, a layout inversion, or the signature) and record
            what changed and why in a _comment.
    STEP 7  Record the decision as designDirection in client-intake.json.

  ── designDirection block (drop into client-intake.json) ────────────────────

    "designDirection": {
      "preset": "landscaping",
      "palette": {
        "brand":      "#14532D",
        "surface":    "#F4F7F2",
        "surfaceAlt": "#E8F0E9",
        "accent":     "#A16207",
        "highlight":  "#15803D",
        "text":       "#14532D"
      },
      "type": { "display": "Bricolage Grotesque", "body": "Inter" },
      "signature": "deep-green full-bleed hero + topographic contour line",
      "_comment": "GreenEdge. Locked direction, not seeded. Gold accent chosen
                   over template terracotta to break cluster-1."
    }

  ── palette role -> template token mapping ──────────────────────────────────

        brand      ->  --brand-dark   (bg-brand-dark, dark hero, footer)
        surface    ->  --paper        (bg-paper, primary light surface)
        surfaceAlt ->  --tint         (bg-tint, alternating sections)
        accent     ->  --accent       (CTA buttons, key actions)
        highlight  ->  --highlight    (eyebrows, small detail marks)
        text       ->  --brand        (text-brand, headings on light)

    Rule: the ACCENT is for action only (CTAs). It is never a section
    background. The BRAND owns the identity surfaces.

║  4.  NOTES / MAINTENANCE                                                      ║
╚══════════════════════════════════════════════════════════════════════════════╝

  · v3.28 NOTE ON THE PRESETS ABOVE. Their palettes are stock Tailwind
    swatches (slate-800 #1E293B, orange-600 #EA580C, blue-600 #2563EB and
    so on) and several TYPE lines name default-stack faces, because both
    came from the ui-ux-pro-max pack. Re-queried in Oct 2026, that pack
    still answers "trade contractor" with blue + orange and Poppins + Open
    Sans. Treat the BONES, SIGNATURE and DO/DON'T lines as the value here.
    For starter colours use the Style Picker sets in
    scripts/pick-palettes.mjs, and for type the kit table or the picker.

  · v1 covers 8 verticals. Add a preset the same way: distinct BASE colour
    family + distinct type personality + a signature that ENCODES the subject.
    Before adding, check it does not share bones with an existing preset.

  · Accents overlap across some presets (orange family: plumbing/cleaning/HVAC).
    That is fine — the BASE differentiates (slate vs teal vs blue). The accent
    is swappable per client; the base is not.

  · Fonts are all Google Fonts. For a premium upgrade, Fontshare faces
    (Satoshi, General Sans, Clash Display) are free alternatives — but keep the
    Google set as the default to avoid @font-face friction on the frozen stack.

  · This file is the frame of reference. When asking for improvements, name the
    preset + guardrail. "Apply 3.5 ROOFING, enforce G1/G2/G3, signature =
    angled roofline." No ambiguity.

  · Source data: github.com/nextlevelbuilder/ui-ux-pro-max-skill (colours.csv,
    typography.csv). Curated and de-clustered — the pack's own cluster-1 entry
    ("Nature Distilled") was deliberately excluded.
